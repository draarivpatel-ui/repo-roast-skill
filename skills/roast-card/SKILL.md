# roast-card: the thing people screenshot

A roast that stays in a markdown file gets read once. A card gets posted. This skill renders the
panel's scores as a 1200x630 SVG with the overall score ring, the tier ("Needs Seasoning",
"Chef's Kiss" and so on), the headline and one quotable line per judge, and a small badge for the
README. Both are generated by deterministic standard-library scripts, so the same scores always
produce the same image.

## Inputs

A card JSON. `roast-repo` writes it to `roast/card.json`; `roast-rematch` writes one with
before and after values. Format:

```json
{
  "repo": "acme/widget",
  "overall": 6.2,
  "headline": "Solid ingredients, questionable cooking.",
  "date": "2026-11-07",
  "mode": "default",
  "previous_overall": 5.1,
  "judges": [
    {"name": "The Paranoid", "role": "Security", "score": 4.5,
     "quote": "Line 42 builds SQL with an f-string.", "previous": 3.0}
  ]
}
```

`previous_overall` and `previous` are optional; when present the card shows `3.0 -> 4.5 (+1.5)`.

## Steps

1. **Find the input.** Use the path the user gave, else `roast/card.json` in the current repo. If
   neither exists but the user typed scores, write them into `roast/card.json` in the format
   above and show it before rendering. If there is nothing to render, suggest `roast-repo` first.

2. **Check the quotes.** Each judge quote is truncated at 74 characters and the headline wraps to
   three lines of 34 characters, with an ellipsis. If a quote would lose its punchline, shorten it
   yourself in card.json (keeping the meaning) rather than letting it be cut mid-joke.

3. **Render the card.**
   ```
   python3 "${CLAUDE_SKILL_DIR}/card.py" --in roast/card.json --out roast/card.svg --badge-path roast/badge.svg
   ```
   It prints the markdown snippet to paste into a README.

4. **Render the badge.**
   ```
   python3 "${CLAUDE_SKILL_DIR}/badge.py" --in roast/card.json --out roast/badge.svg
   ```
   Or from a bare number: `python3 "${CLAUDE_SKILL_DIR}/badge.py" --score 7.4 --out roast/badge.svg`.

5. **Hand it over.** Give the paths and the snippet. Mention that the SVG is self-contained and
   reads well on light and dark pages because it draws its own background. If the user wants a
   PNG for a social post, tell them any SVG-to-PNG tool works (a browser screenshot at 1200x630 is
   enough); do not install converters.

## Score colours and tiers

| Score | Colour | Tier |
|---|---|---|
| below 3.0 | red `#c62828` | Dumpster Fire |
| 3.0 - 3.9 | red `#c62828` | Smoke Alarm |
| 4.0 - 4.9 | orange `#d9480f` | Smoke Alarm |
| 5.0 - 5.9 | orange `#d9480f` | Needs Seasoning |
| 6.0 - 6.9 | amber `#b7791f` | Needs Seasoning |
| 7.0 - 7.9 | amber `#b7791f` | Nicely Done |
| 8.0 - 8.4 | green `#2f855a` | Nicely Done |
| 8.5 - 10 | green `#2f855a` | Chef's Kiss |

## Decision rules

- The card holds six judges. If there are more, the first six are drawn and the script warns.
- Scores are clamped to 0-10 and shown with one decimal.
- All text is cleaned of characters XML forbids and escaped, so quotes with `<`, `&` or quotes
  are safe.

## What NOT to do

- Do not change scores to make the card look better. The card shows what `roast.json` says.
- Do not put a person's name, handle or avatar on the card. The repo is the subject.
- Do not add external fonts, images, scripts or tracking pixels to the SVG.
- Do not post the card or badge anywhere, or commit them. Give the user the files and snippet.

## Hand-off

- No `roast/card.json` yet -> `roast-repo`.
- Want before and after -> `roast-rematch` writes the card JSON with previous scores, then comes
  back here.
